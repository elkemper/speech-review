# 12 — Interface language (RU/EN)

[Index](../SPEC.md) · Prev: [11 — Model updates](11-model-updates.md) · Next:
[13 — Review panel](13-defect-panel.md)

The interface is available in Russian and English. Russian stays the source
language of the message catalogue; English is the first additional language and
the template for adding more.

**Files:** `src/shared/i18n.ts`, `src/shared/locales/ru.ts`,
`src/shared/locales/en.ts`, `src/shared/labels.ts`, `src/renderer/src/i18n.ts`,
`src/main/settings.ts`, `src/main/index.ts`, `src/main/ipc.ts`.

## Stories

### Story 52 — Interface language selector

**Status:** Done · **Priority:** P1

As a user, I want to switch the whole interface between Russian and English,
so that the app matches my language without a rebuild.

- A new setting `Settings.uiLanguage: 'ru' | 'en'` is separate from
  `Settings.language`, which stays the recognition (ASR) language.
- The selector lives in **General → Interface**, before the recognition
  section, with endonyms `Русский` / `English`.
- The choice applies immediately to the renderer, the native application menu,
  native open/save dialogs, progress messages and user-facing errors.
- `<html lang>` follows the selected language.
- A fresh install (no settings file) takes the UI language from
  `app.getLocale()`: `ru*` → `ru`, `en*` → `en`, anything else → `ru`.
  An existing settings file without `uiLanguage` is migrated to `ru`.
- The setting is persisted immediately and never enters undo/redo.
- Opening a project does not change the UI language; the recognition language
  keeps being copied from the project.
- Recognition progress/errors are translated when emitted, so a single job
  stays in one language. The settings form is inert during recognition, which
  keeps the job language stable.

### Story 53 — Message catalogue and label helpers

**Status:** Done · **Priority:** P1

As a maintainer, I want all user-facing text in one typed catalogue, so that a
missing translation is a compile error and no UI string is duplicated.

- `src/shared/locales/ru.ts` is the source catalogue (`as const`).
- `src/shared/locales/en.ts` is typed as `Record<MessageKey, string>`; a
  missing or extra key fails `npm run typecheck`.
- `translate(lang, key, params?)` interpolates `{name}` placeholders and falls
  back from the requested language to Russian, then to the key itself.
- Enum labels (defect type, severity, export field, video resolution/quality/
  encoder, transcription phase, yes/no) are helpers in `src/shared/labels.ts`
  that take `lang`. The renderer and the CSV exporter share them.
- Numeric/date formatting is language-aware: `formatShortSeconds`,
  `formatBytes`, `formatEta`, dialog clocks and project dates.
- Russian filler lexicons in `src/shared/defects.ts` are recognition data, not
  copy, and are not translated.

### Story 54 — Machine-stable export values

**Status:** Done · **Priority:** P1

As a data consumer, I want exported values to be language-independent, so that
downstream tools do not break when the interface language changes.

- CSV row values are always English: type and severity names, `yes`/`no` for
  `cut` and `confirmed`.
- CSV column headers stay machine field ids (`start_tc`, `type`, …).
- JSON export is unchanged (keys and enum ids only).

## Acceptance criteria

### Story 52

- [ ] General has an **Interface** section with a UI-language select.
- [ ] Switching the language updates all visible UI text without a reload.
- [ ] The native menu and the About panel use the selected language after a
      switch or a restart.
- [ ] Native open/save dialog titles and filters use the selected language.
- [ ] `document.documentElement.lang` matches the selected language.
- [ ] No settings file → language from the system locale (`ru`/`en`, else
      `ru`); file without the field → `ru`.
- [ ] The setting persists immediately and is absent from `settings.json`
      history entries and from `EditableProjectState`.
- [ ] Opening a project preserves `uiLanguage` and still copies the
      recognition language.
- [ ] Progress and user-facing errors from the main process are translated.
- [ ] Technical tails (`ffmpeg` stderr, SHA-256, WAV/`words.json` parser text)
      may stay untranslated.

### Story 53

- [ ] `npm run typecheck` fails when the English catalogue misses a key.
- [ ] `translate` handles interpolation, unknown keys and the Russian fallback.
- [ ] Defect/severity/export-field/video labels are read from one module by
      both the renderer and the CSV exporter.
- [ ] Unit labels and decimal separators follow the UI language.
- [ ] Filler word lists are unchanged in both languages.

### Story 54

- [ ] CSV emits `filler`/`yes`/`no` etc. regardless of UI language.
- [ ] CSV headers are unchanged field ids.
- [ ] JSON output is unchanged.

## Verification

- `npm run typecheck`, `npm test`, `npm run build`.
- `test/i18n.test.ts` covers catalogue parity, interpolation, fallback,
  normalization and plural forms.
- Grep checks in `docs/DEVELOPMENT.md` are clean.
- Runtime (Electron, menu, dialogs, recognition progress) must be verified on
  macOS; the Linux container cannot run Electron or the engine.
